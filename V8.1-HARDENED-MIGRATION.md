# Dhatterwal Suhag Bhandar V8.1 Hardened — Migration

## What changed
- Server-side order totals: the browser subtotal/total/discount are no longer trusted.
- Server-side product existence, price, quantity and stock validation.
- Atomic-ish stock reservation under a Script Lock, with rollback if the Orders write fails.
- Random non-sequential order IDs.
- Public order tracking now searches only the matching order row instead of loading the full Orders sheet.
- Admin products/orders/dashboard reads now use POST, not GET URLs containing the admin key.
- Public catalog, reviews and promo responses use short-lived Apps Script Cache.
- Review summaries are returned directly by the backend instead of shipping every review to the homepage.
- Promo max-use counters are maintained in a lightweight `uses` column; one-per-customer checks use a hidden `PromoCustomers` sheet containing hashes, not phone numbers.
- Telegram notification is outside the order commit path, so Telegram outages cannot make a successful order look like a failed order.
- Frontend checkout now fails closed: it will not clear the cart or claim success when the Sheet backend rejects/fails.

## Google Sheet migration
1. Replace the existing Apps Script `code.gs` with the supplied `code.gs`.
2. Deploy a **new Web App version** (or update the deployment) so the website calls the hardened code.
3. Keep the existing `Products`, `Orders`, `Reviews`, `OrderItems` and `Promos` tabs. No product-table redesign is required.
4. The `Promos` sheet may optionally add a `uses` column. The script will create it automatically on the first promo redemption if it is missing.
5. `PromoCustomers` is created automatically only when a `onePerCustomer=yes` promo is actually used; it is hidden and stores hashes.
6. Set a real `ADMIN_KEY` in Apps Script before deployment. Do not use the example default.
7. Keep Telegram credentials blank unless you use Telegram notifications. Prefer moving those secrets into Apps Script Properties in a later hardening pass.
8. No change to the public `Products` URL/configuration is required beyond ensuring it points to the updated deployment URL.

## Important behavior
The storefront can still show a locally calculated subtotal/UPI amount for responsiveness, but the order accepted by the backend is based on the current Google Sheet price and stock snapshot. If a product changed or sold out while a customer was checking out, the order is rejected rather than silently changing inventory or accepting an invalid order.

## Validation performed in the build environment
- All JavaScript files pass `node --check`.
- `code.gs` passes a JavaScript syntax parse after temporarily treating it as `.js`; Apps Script globals are runtime-provided.
- Scanned the project for old admin GET URLs carrying `ADMIN_KEY`: none remain.
