VARIANTS: Create a separate product for each size/colour combination, each with a unique ID, price, MRP and stock quantity. Give all related rows the same Variant group (e.g. kalyani-bra), and labels such as 32 / Skin or 34 / Black. Leave shared Available sizes off for these rows. Customers can switch between them on the product page. Checkout, order history, stock deductions and cancellation refunds use the actual SKU. Variant rows remain individually searchable in the catalogue.

SIZE PRICES: Existing shared-size products can use 32B=299, 34B=329. Other sizes use normal price. Shared-size products still share a stock quantity. Checkout recalculates size prices from the sheet.

COMBOS: Create a product with Combo contents, a combo price, MRP and stock quantity counting prepared sets. Component inventory is managed separately; this does not automatically deduct component products.

MRP / RELATED: Existing discount badges and related-product sections are preserved. Related suggestions now exclude unavailable products and other variants of the same item.

OFFERS: Active codes in the Promos sheet appear on the home page and can be copied. The existing checkout validates usage limits and customer eligibility. Offers may be subject to those limits.

EFFICIENCY RELEASE:
- Search text and product lookups are prepared once per catalogue update.
- Repeated cart lookups reuse parsed storage; changes from other tabs still refresh it.
- Unchanged cart reconciliation no longer writes storage or dispatches refresh events.
- Home and checkout promo loads share a request and short-lived cache.
- Scroll reveals reuse one observer; translation batches avoid repeated descendant scans.
- Currency formatting reuses one formatter; action updates skip unchanged button HTML.
- Hindi/emoji backend cache chunks stay within byte limits and use batched reads/writes.
- Cache failures fall back to live operations. See Google API reference: https://developers.google.com/apps-script/reference/cache/cache
- Variant labels and combo labels appear in cards; sized prices show From pricing.
- Customer-facing new labels have Hindi translations. Shop/admin records stay English.

Validation: JavaScript/Apps Script syntax, local asset references, checkout pricing and stock cases, cart repair/cross-tab refresh, shared promo requests, and cache eviction/outage/Unicode cases passed. Local benchmark: 1,000 cart quantity lookups over 100 saved lines required 1 JSON parse versus 1,000 in the previous ZIP. This is a focused benchmark, not a whole-site speed claim.
